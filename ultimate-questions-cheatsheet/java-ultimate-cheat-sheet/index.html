Answers

1) What are the main features of Java? (Updated for Java 21)

Answer: Think “POSH-R” + Modern Scalability.

  • Platform Independent: “Write Once, Run Anywhere” via the JVM.
  • Object-Oriented: Everything is centered around objects (and now Records for data).
  • Simple & Secure: No pointers, automatic memory management, and a robust security manager.
  • Highly Robust: Strong exception handling and Garbage Collection.
  • Modern Concurrency: Now includes Virtual Threads (Project Loom) for massive scalability.
// Modern Java 21 Feature: Virtual Threads
public class Main {
    public static void main(String[] args) {
        // Creating a virtual thread - lightweight and efficient!
        Thread.ofVirtual().start(() -> {
            System.out.println("Hello from a Virtual Thread!");
        });
    }
}

2) What is the latest version of Java?

Answer: Java 21 is the current major LTS (Long Term Support) version. It introduced stable Virtual Threads and Sequenced Collections. Java 25 is expected to be the next LTS.

3) What are the fundamental principles of object oriented programming?

Answer: Remember A-PIE:

  1. Abstraction: Hiding complexity (Interfaces/Abstract Classes).
  2. Polymorphism: One interface, many forms (Overloading/Overriding).
  3. Inheritance: Acquiring properties from a parent (now enhanced with Sealed Classes for controlled inheritance).
  4. Encapsulation: Protecting data (using private fields and modern Records).

4) What do you mean by inheritance in Java?

Answer: It allows a “Child” class to inherit fields and methods from a “Parent” class.

class Animal {
    void eat() { System.out.println("Eating..."); }
}

class Dog extends Animal {
    void bark() { System.out.println("Barking..."); }
}

// Dog now has both eat() and bark() methods.

5) What are the different types of inheritance?

Answer:

  1. Single: A -> B
  2. Multilevel: A -> B -> C
  3. Hierarchical: A -> B, A -> C
  4. Multiple: (Only via Interfaces)
  5. Hybrid: Combination of the above.

6) does Java supports multiple inheritance? If not, why?

Answer: No, not through classes. Why? To avoid the Diamond Problem. If Class C extends both A and B, and both have a method run(), Class C wouldn’t know which one to execute.

7) If Java doesn’t supports multiple inheritance, then how do you implement multiple inheritance in Java?

Answer: Using Interfaces. A class can implement as many interfaces as it needs.

interface Swimmer { void swim(); }
interface Flyer { void fly(); }

class Duck implements Swimmer, Flyer {
    public void swim() { System.out.println("Swimming..."); }
    public void fly() { System.out.println("Flying..."); }
}

8) What is the parent class of all classes in Java?

Answer: java.lang.Object. Every class you create implicitly extends Object.

9) Do interfaces also inherited from java.lang.Object class?

Answer: No. Interfaces do not extend Object. However, they implicitly declare all of Object’s public methods (like toString(), equals()), so any implementation of an interface will have these methods.

10) How do you restrict a member of a class from inheriting to it’s sub classes?

Answer: Use the private modifier. Private members are only visible within their own class.

11) Can a class extend itself?

Answer: No. It would cause a compile-time error.

12) Do constructors and initializers also inherited to sub classes?

Answer: No. Constructors are not inherited. However, the subclass constructor must call the parent constructor (implicitly or explicitly via super()).

13) What happens if both, super class and sub class, have a field with same name?

Answer: This is called Variable Hiding. The subclass field “hides” the superclass field.

class Parent { String name = "Parent"; }
class Child extends Parent { 
    String name = "Child"; 
    void print() {
        System.out.println(name);       // Child
        System.out.println(super.name); // Parent
    }
}

14) Do static members also inherited to sub classes?

Answer: Yes, but they are not overridden; they are hidden. You should access them using the class name.

15) What is the difference between super() and this()?

Answer:

  • super(): Calls the Parent class constructor.
  • this(): Calls another constructor in the Same class. Both must be the first line in a constructor.

16) What are the differences between static initializers and instance initializers?

Answer:

  • Static Initializer (static {}): Runs once when the class is loaded.
  • Instance Initializer ({}): Runs every time an object is created, before the constructor.

Answer: The process of one constructor calling another constructor (using this() or super()).

Answer: No. The parent exists before the child; it has no knowledge of the child’s constructors.

Answer: No. It must be void.

if (obj instanceof String s) {

50) What is polymorphism in Java?

Answer: “Many forms.”

  2. Dynamic (Runtime): Method Overriding.

51) What is method overloading in Java?

Answer: Same method name, different parameter list (type, number, or order) within the same class.

52) What is the method signature?

Answer: Method Name + Parameter List. (Return type and modifiers are NOT part of the signature).

53) How do compiler differentiate overloaded methods from duplicate methods?

Answer: By the Method Signature. If the name and parameters are identical, it’s a duplicate.

54) Can we declare one overloaded method as static and another one as non-static?

Answer: Yes. As long as the signatures differ, the static/non-static modifiers don’t matter for overloading.

55) Is it possible to have two methods in a class with same method signature but different return types?

Answer: No. It will cause a compile-time error because the signature (name + params) is what matters for uniqueness.

Answer: No. You can have overloaded methods with different access levels (private, public, etc.).

57) Can overloaded methods be synchronized?

Answer: Yes.

60) Overloading is the best example of dynamic binding. True or false?

Answer: False. Overloading is Static Binding (resolved at compile-time). Overriding is Dynamic Binding.

61) Can overloaded method be overrided?

Answer: Yes. You can override any of the overloaded forms in the subclass.

62) What is method overriding in Java?

Answer: Redefining a parent class method in the subclass with the exact same signature.

63) What are the rules for method overriding?

Answer:

  1. Same Signature: (Name + Params).
  2. Compatible Return Type: (Can be a subclass - Covariant Return Type).
  3. Visibility: Cannot be reduced (e.g., public cannot become private).
  4. Exceptions: Cannot throw broader checked exceptions.

64) Can we override static methods?

Answer: No. Static methods belong to the class, not instances. If you define the same static method in a subclass, it’s called Method Hiding.

Answer: It becomes Overloading, not overriding.

66) Can we override protected method as public?

Answer: Yes. You can increase visibility, but you can’t decrease it.

class Parent { Number get() { return 1; } }
class Child extends Parent { Integer get() { return 2; } } // OK!

68) Can we override a method without throws with a method with throws?

Answer: Only for Unchecked Exceptions (RuntimeException). You cannot add new Checked exceptions.

69) Can we change SQLException to NumberFormatException while overriding?

Answer: Yes. NumberFormatException is unchecked, so it’s always allowed.

70) Can we change exception from unchecked to checked?

Answer: No.

71) How do you refer super class version of overridden method?

Answer: Using the super keyword: super.myMethod().

72) Can we override private methods?

Answer: No. Subclasses can’t see them.

Answer: No.

Answer: Yes.

208) What is an object lock (monitor)?

265) What are Streams?

Answer: No. Streams do not store data. They only convey data from a source through a pipeline of computational steps.

267) Intermediate vs Terminal operations?

Answer:

268) What is a Pipeline of operations?

Answer: A sequence of one source, zero or more intermediate operations, and one terminal operation.

269) “Implicit iteration” in Streams?

270) Lazy Loading in Streams?

Answer: Intermediate operations are not performed until the terminal operation is invoked. This allows for “short-circuiting” (e.g., finding the first element without checking the whole list).

304) What is an Exception?

Answer: An unwanted or unexpected event that occurs during the execution of a program (at runtime) that disrupts the normal flow of instructions.

305) Exception Handling Mechanism in Java?

Answer: Using five keywords:

  1. try: Block where an exception might occur.
  2. catch: Handles the exception.
  3. finally: Code that always executes (cleanup).
  4. throw: Used to manually throw an exception.
  5. throws: Declares that a method might throw an exception.

306) Error vs Exception?

Answer:

  • Error: Indicates serious problems that a reasonable application should not try to catch (e.g., OutOfMemoryError, StackOverflowError).
  • Exception: Indicates conditions that a reasonable application might want to catch (e.g., IOException, NullPointerException).

307) Statements between try, catch, and finally?

Answer: No. They must form a contiguous block.

308) try block without catch or finally?

Answer: No. It must be followed by at least one catch block or a finally block. (Exception: Try-with-resources in Java 7+).

309) Exception in statement2: Does statement3 execute?

Answer: No. Once an exception is thrown, the rest of the try block is skipped and control transfers to the catch block.

310) Unreachable catch block error?

Answer: Occurs if you put a parent exception class (like Exception) before a child exception class (like IOException) in multiple catch blocks. The parent will catch everything, making the child catch block “unreachable”.

311) Exception Hierarchy?

Answer: Throwable (Root) ├── Error └── Exception ├── RuntimeException (Unchecked) └── Other Exceptions (Checked)

312) Runtime Exceptions examples?

Answer: NullPointerException, ArrayIndexOutOfBoundsException, ArithmeticException, NumberFormatException. These are Unchecked exceptions.

313) What is OutOfMemoryError?

Answer: Thrown when the JVM cannot allocate an object because it is out of memory, and no more memory could be made available by the garbage collector.

314) Checked vs Unchecked Exceptions?

Answer:

  • Checked: Checked at compile-time. You must either handle them or declare them in throws. (E.g., IOException).
  • Unchecked: Occur at runtime. Compiler does not force you to handle them. (E.g., NullPointerException).

315) ClassNotFoundException vs NoClassDefFoundError?

Answer:

  • ClassNotFoundException: Thrown when you try to load a class by its name using Class.forName() but the class is not on the classpath.
  • NoClassDefFoundError: The class was present at compile-time but is missing at runtime.

316) Statements after finally block if finally returns control?

Answer: No. If the finally block has a return or throw statement, any code after it is unreachable.

317) Does finally execute if try/catch has a return?

Answer: Yes. The finally block always executes even if there is a return statement in the try or catch blocks.

318) Throw exception manually?

Answer: Yes, using the throw keyword.

if (age < 18) {
    throw new ArithmeticException("Not eligible to vote");
}

319) Re-throwing an exception?

Answer: Catching an exception and then throwing it again (perhaps after logging it).

320) Use of throws keyword?

Answer: To declare that a method might throw certain exceptions, delegating the responsibility of handling them to the caller.

321) Clean up operations in finally block?

Answer: Because the finally block is guaranteed to execute, it’s the perfect place to close database connections, files, or network sockets to prevent resource leaks. Modern Context: Use Try-with-resources for classes that implement AutoCloseable.

322) final vs finally vs finalize?

Answer:

  • final: Modifier (constant variable, non-overridable method, non-inheritable class).
  • finally: Block in exception handling (guaranteed execution).
  • finalize(): Method called by Garbage Collector before destroying an object (Deprecated since Java 9, Do not use!).

323) Create customized exceptions?

Answer: Extend the Exception class (for checked) or RuntimeException class (for unchecked).

public class MyException extends Exception {
    public MyException(String message) { super(message); }
}

324) ClassCastException?

Answer: Thrown when you try to cast an object to a subclass of which it is not an instance.

325) throw vs throws vs throwable?

Answer:

  • throw: Keyword used to manually throw an exception.
  • throws: Keyword used in method signature to declare potential exceptions.
  • Throwable: The root class for all Errors and Exceptions.

326) StackOverflowError?

Answer: Thrown when the stack memory is full, usually due to infinite recursion.

327) Override method with broader checked exception?

Answer: No. Subclasses cannot throw broader checked exceptions than their parents.

328) Chained Exceptions?

Answer: Relating one exception to another. E.g., catching a low-level exception and throwing a high-level one while preserving the original “cause”.

try {
    // some code
} catch (IOException e) {
    throw new MyException("High level error", e); // 'e' is the cause
}

329) Superclass for all Errors and Exceptions?

Answer: java.lang.Throwable.

330) Legal combinations of try-catch-finally?

Answer:

  1. try-catch
  2. try-catch-finally
  3. try-finally

331) Use of printStackTrace()?

Answer: Prints the exception name, description, and the sequence of method calls (stack trace) that led to the exception. Extremely useful for debugging.

332) Checked Exceptions examples?

Answer: IOException, SQLException, ClassNotFoundException, FileNotFoundException.

333) Unchecked Exceptions examples?

Answer: NullPointerException, ArithmeticException, NumberFormatException, ArrayIndexOutOfBoundsException.

334) Try-with-resources?

Answer: Introduced in Java 7, it’s a try block that automatically closes resources at the end. The resources must implement AutoCloseable.

    System.out.println(br.readLine());
} catch (IOException e) {
    e.printStackTrace();
} // br is automatically closed here!

335) Benefits of try-with-resources?

Answer:

  1. Cleaner code (no explicit close() in finally).

338) Java Collection Framework?

Answer: A set of classes and interfaces that implement commonly used data structures (Lists, Sets, Maps) to store and manipulate groups of objects efficiently.

339) Root interface of Collection Framework?

Answer: java.util.Collection. (Note: Iterable is the super-interface of Collection).

340) Four main core interfaces of Collection Framework?

Answer:

  1. List
  2. Set
  3. Queue
  4. Map (Map doesn’t extend Collection, but is part of the framework).

341) Collection Framework Hierarchy?

Answer:

  • Collection
    • List (ArrayList, LinkedList, Vector, Stack)
    • Set (HashSet, LinkedHashSet, TreeSet)
    • Queue (PriorityQueue, Deque -> ArrayDeque)
  • Map (HashMap, LinkedHashMap, TreeMap, Hashtable)

342) Why Map doesn’t extend Collection?

Answer: Because they are fundamentally different. Collection stores single elements, while Map stores Key-Value pairs.

343) What is Iterable interface?

Answer: The root interface of the whole hierarchy. Any class implementing Iterable can be used in an enhanced for-loop.

344) Characteristics of List?

Answer:

  1. Ordered (maintains insertion order).
  2. Allows Duplicates.
  3. Index-based access.

345) Major implementations of List?

Answer: ArrayList, LinkedList, Vector.

346) Characteristics of ArrayList?

Answer:

  1. Resizable array.
  2. Fast random access ($O(1)$).
  3. Slow insertion/deletion in the middle ($O(n)$) because of element shifting.

347) Three marker interfaces in ArrayList?

Answer:

  1. RandomAccess
  2. Serializable
  3. Cloneable

348) Default initial capacity of ArrayList?

Answer: 10.

349) Main drawback of ArrayList?

Answer: Shifting. Adding or removing an element from the middle requires shifting all subsequent elements, which is slow for large lists.

Answer:

  • ArrayList: Not synchronized (Faster).

352) Why avoid Vector?

Answer: Because it synchronizes every operation even if only one thread is using it, leading to poor performance.

353) Growth of Vector vs ArrayList?

Answer:

  • Vector: Doubles its size (100% growth).
  • ArrayList: Increases by 50%.

354) Characteristics of Queue?

Answer: FIFO (First-In, First-Out). Elements are added at the tail and removed from the head.

355) Important methods of Queue?

Answer:

  • Insert: add(), offer()
  • Remove: remove(), poll()
  • Examine: element(), peek()

356) Queue vs List?

Answer: Lists allow random access. Queues typically only allow access to the head/tail elements.

357) Popular type implementing both List and Queue?

Answer: LinkedList.

358) Characteristics of LinkedList?

Answer:

  1. Doubly-linked list.
  2. Fast insertion/deletion ($O(1)$) as no shifting is needed.
  3. Slow random access ($O(n)$) because you must traverse from the start/end.

359) ArrayList vs LinkedList?

Answer:

  • Search: ArrayList is faster ($O(1)$ vs $O(n)$).
  • Update/Delete: LinkedList is faster ($O(1)$ vs $O(n)$) once the position is found.

360) What is PriorityQueue?

Answer: A queue where elements are ordered by their priority (either natural order or a custom Comparator), not their insertion time.

361) What are Deque and ArrayDeque?

Answer:

  • Deque (Double-Ended Queue): Allows insertion/removal from both ends (Stack & Queue combined).
  • ArrayDeque: A resizable array implementation of Deque. It’s faster than Stack (when used as a stack) and faster than LinkedList (when used as a queue).

362) Characteristics of Sets?

Answer:

  1. No Duplicates allowed.
  2. Unordered (usually).
  3. Allows at most one null element (implementation-dependent).

365) Characteristics of HashSet?

Answer:

  1. Backed by a HashMap.
  2. Unordered.
  3. Fastest Set implementation ($O(1)$ for add/contains).

366) How HashSet works internally?

Answer: It uses a HashMap where your elements are stored as Keys, and a constant dummy value (a private static Object PRESENT) is stored as the Value.

367) Characteristics of LinkedHashSet?

Answer: Maintains Insertion Order using a doubly-linked list running through the hash table.

368) When to prefer LinkedHashSet?

Answer: When you need unique elements but also need to preserve the order in which they were added.

369) How LinkedHashSet works internally?

Answer: It extends HashSet and uses a LinkedHashMap internally instead of a regular HashMap.

370) What is SortedSet?

Answer: A Set that maintains elements in sorted order (natural order or custom Comparator). Implementation: TreeSet.

371) What is NavigableSet?

Answer: An extension of SortedSet that provides navigation methods like lower(), floor(), ceiling(), and higher(). Implementation: TreeSet.

372) Characteristics of TreeSet?

Answer:

  1. Sorted order.
  2. Backed by a Red-Black Tree.
  3. Does not allow null (throws NPE).
  4. $O(log n)$ time for operations.

373) HashSet vs LinkedHashSet vs TreeSet?

Answer:

  • HashSet: Fastest, no order.
  • LinkedHashSet: Insertion order.
  • TreeSet: Sorted order.

374) Iterator vs ListIterator?

Answer:

  • Iterator: Forward traversal only. Works on any Collection.
  • ListIterator: Bi-directional traversal. Works only on Lists. Allows modification during iteration.

375) Map interface vs others?

Answer: Maps use Key-Value pairs. You access data via keys, not indexes. It does not extend the Collection interface.

376) Popular implementations of Map?

Answer: HashMap, LinkedHashMap, TreeMap, ConcurrentHashMap, Hashtable.

377) Characteristics of HashMap?

Answer:

  1. Unordered.
  2. Allows one null key and multiple null values.
  3. Not synchronized (not thread-safe).
  4. $O(1)$ average time complexity.

378) How HashMap works internally? (The “Million Dollar” Interview Question)

Answer:

  1. Array of Buckets: Stores Node<K,V> objects.
  2. hashCode(): Finds the bucket index.
  3. Collision Handling: Multiple keys in one bucket form a LinkedList.
  4. Treeification (Java 8+): If a bucket exceeds 8 nodes, the LinkedList converts to a Balanced Tree (Red-Black Tree) for better performance ($O(log n)$ vs $O(n)$).
  5. equals(): Used to find the exact key within a bucket.

379) What is Hashing?

Answer: The process of converting an object into an integer representation (hash code) using a formula. It’s used to quickly locate objects in a collection.

380) Initial capacity of HashMap?

Answer: 16.

381) Load factor of HashMap?

Answer: 0.75. It means the map will resize (double) once it is 75% full.

382) HashMap Threshold?

Answer: Threshold = Capacity * Load Factor. (e.g., $16 * 0.75 = 12$).

383) What is rehashing?

Answer: When the map’s size exceeds the threshold, it doubles the internal array size and recalculates the bucket index for all existing entries to redistribute them.

384) Impact of capacity and load factor?

Answer:

  • High capacity: Reduces rehashing but wastes memory.
  • Low load factor: Reduces collisions but increases rehashing.
  • Default (16, 0.75): Optimal balance for most use cases.

Answer:

  • HashSet: Implements Set. Stores objects.
  • HashMap: Implements Map. Stores Key-Value pairs. (HashSet uses HashMap internally).

Answer: ConcurrentHashMap is thread-safe and highly performant because it uses segment-level locking (or bucket-level locking in modern versions) instead of locking the whole map.
